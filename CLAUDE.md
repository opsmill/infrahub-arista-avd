## Project Overview

This is an Infrahub repository solution for AI datacenter infrastructure management. It defines schemas, generators, and transforms for modeling network fabric hierarchies (Fabric → Pod → Rack → Device).

## Commands

### Setup
```bash
uv sync --all-packages
```

### Infrahub Services
```bash
inv start          # Start Infrahub with docker-compose
inv stop           # Stop containers
inv destroy        # Stop and remove containers, networks, volumes
inv restart        # Restart all services (or specific: inv restart --component=<name>)
```

### Building
```bash
export INFRAHUB_BASE_VERSION=local
uv run inv build   # Build custom docker image
```

### Loading Data
```bash
inv load           # Load schema, menus, objects, and repository
inv load-schema    # Load schemas only
inv load-menu      # Load menus only
```

### Testing
```bash
pytest tests                           # Run all tests
pytest tests/unit                      # Unit tests only
pytest tests/integration               # Integration tests only
pytest tests/unit/test_computed_attribute.py  # Single test file
```

### Linting
```bash
inv lint           # Run all linters (yamllint, ruff, mypy)
inv lint-ruff      # Ruff only

inv lint-mypy      # Mypy only

```

## Architecture

### Schema Hierarchy
Schemas in `schemas/` define the Infrahub data model:
- **logical_design.yml**: `NetworkFabric` → `NetworkPod` (hierarchical building blocks)
- **device.yml**: `NetworkDevice`, `NetworkInterface`, `NetworkLink`
- **physical_location.yml**: `LocationHall` → `LocationRack` hierarchy
- **ipam.yml**: `IpamIPAddress`, `IpamIPPrefix`
- **generator.yml**: `GeneratorTarget` generic with checksum tracking

### Generator System
Generators in `generators/` create infrastructure from templates:
- **FabricGenerator**: Creates super-spine switches, allocates IP pools from FabricSupernetPool
- **PodGenerator**: Creates spine switches per pod
- **RackGenerator**: Creates leaf switches per rack

Each generator extends `InfrahubGenerator` and `GeneratorMixin` (from `src/solution_ai_dc/generator.py`). The `GeneratorMixin.calculate_checksum()` method tracks related node changes to determine when regeneration is needed.

Generator queries (`*_generator_query.py`) are Pydantic models matching GraphQL response structures.

### Transforms
- **Python transforms** (`transforms/*.py`): `ComputedInterfaceDescription`, `CablingPlan`
- **Jinja2 transforms**: Device startup configs via `transforms/templates/startup_config.j2`

### Protocols
`src/solution_ai_dc/protocols.py` contains typed protocol classes generated by `infrahubctl protocols`. These provide IDE support for Infrahub node types.

### Object Data Files
`objects/` contains numbered YAML files loaded in order:
- Groups → Manufacturers → Device Types → IPAM → Profiles → Templates → Fabric → Racks

## Key Configuration Files
- `.infrahub.yml`: Defines queries, generators, transforms, and artifact definitions
- `repository.yml`: CoreRepository definition for Infrahub
- `docker-compose.override.yml`: Local development overrides
